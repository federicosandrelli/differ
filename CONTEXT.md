# Domain language

Terms the code uses. A name here is the name in the code.

- **Pull request (PR).** What a page shows: one GitHub pull request, identified by `owner/repo#number` (a `PullRef` in `github.py`) and built per head commit.
- **Status.** Where a PR stands on GitHub: `open`, `draft`, `merged` or `closed` (`github.Status`), shown as an icon in the tab, the sidebar and the start page. A page shows the status it was built with until its comments load, then the one `comments.fetch` reads from GitHub, since a merge or a close leaves the head commit, and so the cached page, as it was. The start page's list keeps its own status per PR in `recent.json`: the page's when the PR joins the list, then GitHub's each time the list is fetched (`refresh` in `recent.py`).
- **Standing.** A PR's status and the login of its author, as GitHub reports them now (`github.Standing`, from `github.pr_standings`, which also returns the viewer's login).
- **Section.** One of the three lists of the start page (`SECTIONS` in `recent.py`): `mine` for the PRs the viewer wrote, `other` for the rest, and `merged` for every merged PR, whoever wrote it. `section_of` places a PR by its status and author and the viewer's login, all saved in `recent.json`. Each section lists at most `KEPT` PRs, newest first; an older one leaves the list when its section is full.
- **Diff.** What `classify.py` reads (`classify.Diff`): the patch from the merge base to the head, the content of every changed file on each side, and the paths marked `linguist-generated`.
- **File.** One changed file of the PR, with its hunks, runs and content on one side (`content_side`: the new file, or the old one for a deleted file). A binary file has no hunks; `binary` holds its size in bytes on each side.
- **Hunk.** A unified-diff hunk from GitHub's diff of the PR, as lines `[tag, old, new, text]`.
- **Run.** A maximal block of changed hunk lines (removed then added) with a class: `substantive`, or the noise classes `import`, `rename`, `whitespace`, `moved`. `noise` says whether the page folds it: a run of a noise class does, except the rename run that defines the new name.
- **Rename.** A name that changes the same way in at least two runs, or the module or file name of a renamed file. Its **origin** (`classify.Origin`) is where it is defined: the renamed file, or the first class, def, annotation or assignment of the new name.
- **Row.** One line of the diff table: a removed line (`del`), an added line (`add`) or an unchanged one (`ctx`).
- **Row key.** The address of a row on its own side: `O<old line>` for a removed line, `L<new line>` for the rest. Defined in `page/25-address.js`; threads, search hits, deep links and element ids all name rows by key. The number cell that shows a row's key line (`td.n.key`: the old number of a removed line, the new number of the rest) is the row's comment button.
- **File view.** The rows of one file grouped into blocks with every fold decided (`fileBlocks` in `page/30-rows.js`). `drawn(block)` is what the diff table draws of a block: the rows that show and where its fold row goes; the table, the height estimate, the search and `reveal(file, key)`, which opens whatever hides a row, all read it; `toggleFold(id)` answers a click on a fold row.
- **Fold.** Something the view hides until opened: the middle of a context block, a noise run, several noise runs grouped as one, or an import section. A fold has an opaque **fold id** that only the file view reads. A fold row stays when its fold opens, so a second click folds the lines again. Several folds merged into one, grouped noise runs or closed folds with nothing drawn between them (`joinFolds`), open as one fold: one fold row above every line they hide. Opening a merged fold keeps its lines open as an **open range**, and any fold that hides a line of an open range shows open, whatever shape the folds take later. No fold reaches across the edge of an open range, so the folds next to it open and close on their own. An import section or a noise run is **locked** while a pinned row holds it open: its fold row names it but takes no clicks.
- **Inline fold.** The fold of a context block that holds the body lines between the start of the class, function or call around a change and the lines next to the change. It draws as a chip on its own row instead of a fold row, and the chip counts as `CHIP_LINES` of the `RADIUS` lines shown next to a change.
- **Pinned row.** A row a fold may never hide: a row with a thread, or the row with the comment being written. A row with a thread or the comment being written inside an open range pins nothing: the folds keep their shape and show open around it.
- **Search hit.** A row holding the query that the reader can see: a row the file view shows (`viewHits` in `page/10-files.js`), in an open section of a shown file. Hits never open a fold. While searching, the page shows only the files with a hit (`visibleFiles`), but the tree still lists every file (`fileInTree`) and shades the files and folders without one. The **current hit** (`state.hit`) is the one Enter last went to, or the first hit of the file the tree last opened; Enter goes on from it, and its matches pop when it changes (`popHit` in `page/80-main.js`). A match is one `<mark>`, even across highlighter tokens.
- **File search.** The search over file paths instead of rows (`state.fileSearch`), turned on and off by Shift+Cmd+F, which keeps the query, and off by Cmd+F and by Escape, which ends the search. It finds the files whose path holds the query (`found` in `page/10-files.js`) and shows them as the search over rows does for files with a hit, but the tree lists only those files. It marks no rows; its hits are the files it finds (`allHits`), so Enter goes from file to file.
- **Thread.** A GitHub review thread, placed on the row its line maps to, or listed as outdated when its line is gone.
- **Verdict.** The viewer's latest approval or change request and the commit it reviewed (`verdict` from `comments.fetch`), or none when GitHub dismissed it. While the verdict is on the head commit, the Review button names it and the page and the server refuse the same verdict again (`headVerdict` in `page/50-comments.js`, `REPEATS` in `comments.py`). A pending review started before a push reviews the commit it started on, so its verdict, once sent, is on an older commit, as on GitHub.
- **Shell.** The tabbed document at `/` that holds the start page and one page per PR in iframes. Its two sides are `shell/tabs.js` (the strip and the frames) and `shell/frame.js` (what a page inside it does); the messages between them are known only to those two files. The desktop app's "Close Tab" menu item (Cmd+W) reaches the shell as a `close-tab` event on its window, sent from `src-tauri/src/main.rs`. A page reaches the shell through `SHELL`, null when the page is the top-level document.
- **Tab.** One entry in the shell's strip: the home tab for the start page, or a PR page, keyed by its path. A PR page reports whether it holds a **draft**, text the user typed and has not sent (`hasDraft` in `page/50-comments.js`); closing a tab with a draft takes a second close within a few seconds.
- **Theme.** The colour scheme (`light`, `sepia`, `dark`) saved as `dr:theme`, dark by default. `shell/theme.js` applies it in every document and keeps the native window and the other open documents in step; the palettes live in `render.py`.
- **Tooltip.** The `.tooltip` that `shell/tooltip.js` shows for any element with a `title`, in every document the server sends: after the pointer rests on the element for 300 ms, or right away when the pointer comes back to the same element less than 500 ms after its tooltip closed. A title that repeats text the element shows in full shows only while some of that text is cut off. Give an element a `title` only when it tells the reader something the screen does not already show, such as the name behind an icon or a full name that may be cut off (the only kind of tooltip the file tree has); never draw a tooltip of its own.
- **Colour token.** A CSS custom property that `palette()` in `render.py` defines for each theme; stylesheets and scripts name tokens, never colours (`tests/test_render.py` checks). Backgrounds: `--bg-canvas`, `--bg-panel` (sidebar, folds, cards), `--bg-inset` (code, pills, badges), `--bg-hover`, `--bg-hover-strong`. Text: `--text`, `--text-secondary`, `--text-muted`, `--text-on-accent`. `--border`. Accent: `--accent`, `--accent-hover`, `--accent-bg`. Selection: `--tree-active-bg`, `--tree-active-fg`, `--row-target-bg`, `--row-selected-bg`, `--comment-pending-bg`, `--search-hit-bg`, `--search-hit-fg`. Overlay: `--backdrop`, the dimmed window behind the docs. Diff: `--add-*`, `--del-*`, `--mod-*`, `--ren-*` (`-fg`, `-bg`, `-num`, `-word`). Syntax: `--syntax-kw`, `--syntax-str`, `--syntax-cmt`, `--syntax-num`, `--syntax-fn`, `--syntax-cls`, `--syntax-builtin`.
- **Editor.** An IDE the page can open a file in (`editors.EDITORS`): VS Code, Cursor, or a JetBrains IDE. The server finds one by the full path of its command line tool in its app bundle (`Editor.command`) and accepts only the id of an installed one. The page saves the reader's choice as `dr:editor`, and uses the first installed editor while it has no saved choice that is installed.
- **Checkout.** The normal clone of a repository, with file contents, that an editor opens (`editors.checkout_dir`): `checkouts/<owner>/<repo>` in the cache, next to the bare clone in `repos/` that builds pages. The first open clones it into a temporary folder and renames that once the clone is complete. Each open runs `gh pr checkout` in it, moves a force-pushed branch to the new head with `git checkout -B` only when that loses no work (`open_file` in `editors.py`), and refuses while it has uncommitted changes to tracked files on the branch of another PR.
- **Bug report.** The prompt for Claude Code that the sidebar's footer builds from a typed description and the page's state (`page/75-bugreport.js`). `LOG` in `page/00-data.js` keeps the recent actions and errors the prompt quotes.
