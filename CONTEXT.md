# Domain language

Terms the code uses. A name here is the name in the code.

- **Pull request (PR).** What a page shows: one GitHub pull request, identified by `owner/repo#number` (a `PullRef` in `github.py`) and built per head commit.
- **Status.** Where a PR stands on GitHub: `open`, `draft`, `merged` or `closed` (`github.Status`), shown as an icon in the tab, the sidebar and the start page. A page shows the status it was built with until its comments load, then the one `comments.fetch` reads from GitHub, since a merge or a close leaves the head commit, and so the cached page, as it was. The list of PRs opened last keeps its own status per PR in `recent.json`: the page's when the PR joins the list, then GitHub's each time the start page asks again (`refresh` in `recent.py`).
- **Standing.** A PR's status and the login of its author, as GitHub reports them now (`github.Standing`, from `github.pr_standings`).
- **Section.** A group of the start page's pull requests with a key, such as `action` or `reviewing`; a column lists the rows of one or more sections. `GROUPS` in `board.py` puts the sections in **columns** (`Column`), three per group: two side by side in a row, each with a **share** of the row's width (3 and 7 for the viewer's own, 1 and 1 for other people's), stacked on a narrow window, and a **folded** column under the row, a `details` that is closed until the reader opens it. The group of the viewer's own PRs has Drafts (`draft`), In review (`action`, `ci` and `review`) and, folded, Merged today (`merged`); the group of other people's has Need a reviewer (`unreviewed`), Being reviewed (`reviewing`, `reviewed` and `others`) and, folded, Merged today (`merged_others`). `own` and `other` place an open PR in one section and give the **reasons** its card shows, in order (`Reason`): each has its words, a **kind** that picks its icon (`render.REASON_ICONS`), and a **tone** (`bad`, `warn`, `ok`, `accent` or empty) that colours it. A card draws each reason as a reason pill with its icon and its words, coloured by its tone, on a line of its own under the repository and the age (`reasons_html`); a quiet card has no reasons. `load` treats a `board.json` with rows without reasons, from an older version, as empty, so the next refresh rewrites it. `classify` sorts the answers to the searches `queries` builds; `unreviewed`, `others` and `merged_others` only hold PRs of followed repositories; `merged` holds the viewer's PRs merged today, and `merged_others` other people's PRs merged today in a followed repository, both by GitHub's date (UTC). A column draws the rows of its sections as one list, without subtitles, in the order of urgency that `Column` gives its sections, and each section newest first; so In review lists the PRs that need the viewer's action, then the ones waiting on CI, then the ones waiting on review, and Being reviewed lists the PRs waiting on the viewer's review, then the ones the viewer reviewed, then the ones someone else reviewed. A column counts the rows of its sections. A section is **full** when a search that feeds it found as many PRs as a search reads (`github.SEARCH_LIMIT`, see `full`), so it may lack rows; its column's count shows a plus, such as "50+". A column without rows shows a dimmed None, so every column keeps its place. A column's list shows its first `SHOWN` cards and a "Show N more" button that shows the rest. The start page keeps an opened list, and an opened folded column, open when the board draws again, until the page reloads, and saves nothing about it. The merged columns are **quiet**: their cards sit on the canvas, one line of title each. The **board** is what `board.json` keeps of GitHub's last answer: the viewer, when it came, the followed repositories it asked about, the rows of each section, and the full sections. `refresh` asks again at most every `REFRESH_SECONDS`, unless the followed repositories changed. Under the groups, **Recently opened** lists the PRs opened today (local time) that no section shows. Under it, the start page's **footer** (`footer_html`) names the viewer and how long ago GitHub last answered, both left out until GitHub has answered, and holds a Settings button, shown only inside the shell. The footer draws with the board, so it stays current. Above the groups, the **repository strip** (`repos_html`) holds a toggle per followed repository the board asked about, with the count of its cards on the whole board outside the folded Merged today columns, and a plus when a full section outside them has some of these cards, and a gear that opens the Settings at the Repositories section; without followed repositories, it holds a hint and a Follow a repository button instead. The reader may turn on any number of toggles; the start page then asks `/board` for those repositories (`repo` parameters), and `sections_html` draws only their rows, in both groups and in Recently opened, so the column counts, None and Show N more count those rows; a full section adds its plus to its column's count only while it has rows. With no toggle on, the board shows every row. A toggle names the repository, or `owner/repo` when two followed repositories share a name. The start page saves the toggles that are on as `dr:boardRepos`, and keeps only the ones the board still draws, so a repository the reader stops following drops out. A toggle click redraws the board from `board.json` without asking GitHub (`cached=1`), and so does the first load with saved toggles, since the server draws the start page with every row. The gear and the Follow a repository button show only inside the shell, as the footer's Settings button does.
- **Start page header.** The title and the field at the top of the start page (`header.start`): the title on the left, and the field with its Open button and its "Open a pull request" label filling the rest of the row, the field's bottom on the title's baseline. On a narrow window the field wraps below the title.
- **Diff.** What `classify.py` reads (`classify.Diff`): the patch from the merge base to the head, the content of every changed file on each side, and the paths marked `linguist-generated`.
- **File.** One changed file of the PR, with its hunks, runs and content on one side (`content_side`: the new file, or the old one for a deleted file). A binary file has no hunks; `binary` holds its size in bytes on each side.
- **File type.** What a file is, from its name (`file_types.FileType`): Python source, Markdown, a PNG image, or `OTHER`. `file_types.of(path)` finds it by the file's name, then by its suffix in any case. `file_types.support` returns its `FileTypeSupport`: the suffixes and names that find it, its highlight.js name, its language, where it is documentation (`Docs`), the name endings of its generated files, and the media type the server sends it with when it is an image.
- **Kind.** What a file is for (`classify.file_kind`): `docs`, `test` or `implementation`. A file is `docs` when its file type is documentation anywhere (`Docs.ALWAYS`, such as Markdown), or only inside a documentation folder (`Docs.IN_DOCS_FOLDER`: an image) and a folder of its path is in `DOCS_DIRS` or ends in `DOCS_DIR_SUFFIX`. A file type that can hold code is never documentation, so code in a docs folder stays `implementation` or `test`. The kind buttons above the tree are All, which shows every file, then Implementation, Tests and Docs, which each show the files of one kind with the count of those files and of their added and removed lines. The buttons wrap onto more lines when they don't fit.
- **Language.** The programming language of a file type (`languages.Language`), or none for a file type such as JSON or an image. `languages.support` returns its `LanguageSupport`: the import lines and symbols of a source, whether a file name without its suffix names a test, whether a line defines a name, and the dotted module name of a path. `file_types.language_support(path)` returns the `LanguageSupport` of a file, or `NO_LANGUAGE` for a file type without a language.
- **Hunk.** A unified-diff hunk from GitHub's diff of the PR, as lines `[tag, old, new, text]`.
- **Run.** A maximal block of changed hunk lines (removed then added) with a class: `substantive`, or the noise classes `import`, `rename`, `whitespace`, `moved`. `noise` says whether the page folds it: a run of a noise class does, except the rename run that defines the new name.
- **Rename.** A name that changes the same way in at least two runs, or the module or file name of a renamed file. Its **origin** (`classify.Origin`) is where it is defined: the renamed file, or the first class, def, annotation or assignment of the new name.
- **Row.** One line of the diff table: a removed line (`del`), an added line (`add`) or an unchanged one (`ctx`).
- **Row key.** The address of a row on its own side: `O<old line>` for a removed line, `L<new line>` for the rest. Defined in `page/25-address.js`; threads, search hits, deep links and element ids all name rows by key. The number cell that shows a row's key line (`td.n.key`: the old number of a removed line, the new number of the rest) is the row's comment button.
- **File view.** The rows of one file grouped into blocks with every fold decided (`fileBlocks` in `page/30-rows.js`). `drawn(block)` is what the diff table draws of a block: the rows that show and where its fold row goes; the table, the height estimate, the search and `reveal(file, key)`, which opens whatever hides a row, all read it; `toggleFold(id)` answers a click on a fold row.
- **Fold.** Something the view hides until opened: the middle of a context block, a noise run, several noise runs grouped as one, or an import section. A fold has an opaque **fold id** that only the file view reads. A fold row stays when its fold opens, so a second click folds the lines again. Several folds merged into one, grouped noise runs or closed folds with nothing drawn between them (`joinFolds`), open as one fold: one fold row above every line they hide. Opening a merged fold keeps its lines open as an **open range**, and any fold that hides a line of an open range shows open, whatever shape the folds take later. No fold reaches across the edge of an open range, so the folds next to it open and close on their own. An import section or a noise run is **locked** while a pinned row holds it open: its fold row names it but takes no clicks.
- **Inline fold.** The fold of a context block that holds the body lines between the start of the class, function or call around a change and the lines next to the change. It draws as a chip on its own row instead of a fold row, and the chip counts as `CHIP_LINES` of the `RADIUS` lines shown next to a change. The run's `enclosing` symbol names that start: the innermost symbol (`languages.Symbol`) with the run's first added line in its body, from `classify.enclosing`. In Python, a symbol is a class, a function, or a call with arguments below the expression it calls, in any expression.
- **Pinned row.** A row a fold may never hide: a row with a thread, or the row with the comment being written. A row with a thread or the comment being written inside an open range pins nothing: the folds keep their shape and show open around it.
- **Search hit.** A row of the file view (`viewHits` in `page/10-files.js`) that holds the query, in an open or closed section of a shown file. Hits never open a fold; Enter opens a closed section when it lands on a hit there. While searching, the page shows only the files with a hit (`visibleFiles`), but the tree still lists every file (`fileInTree`) and shades the files and folders without one. The **current hit** (`state.hit`) is the one Enter last went to, or the first hit of the file the tree last opened; Enter goes on from it, and its matches pop when it changes (`popHit` in `page/80-main.js`). A match is one `<mark>`, even across highlighter tokens.
- **File search.** The search over file paths instead of rows (`state.fileSearch`), turned on by Shift+Cmd+F, which keeps the query, and off by Cmd+F and by Escape, which ends the search. It finds the files whose path holds the query (`found` in `page/10-files.js`) and shows them as the search over rows does for files with a hit, but the tree lists only those files. It marks no rows; its hits are the files it finds (`allHits`), so Enter goes from file to file.
- **Thread.** A GitHub review thread, placed on the row its line maps to, or listed as outdated when its line is gone.
- **Image viewer.** The `dialog` that a click on an image of the overview (the description and the conversation) or of a thread opens over the whole window (`page/65-viewer.js`), unless the click means something else: an image in a summary, or in a link to another file than its own. The left and right arrows step through the images of the same place that the reader can see, going round at the ends, and a count shows where the reader is when there are several. Escape, the ✕ and a click outside the image close it.
- **Sending comment.** A comment or reply the viewer sent, shown at once in its thread (`sendingComments` in `page/50-comments.js`) with a `sending` tag until GitHub takes it. A new thread made this way is `local` until GitHub's copy replaces it; `arrived` says when a load ends the wait for that copy. When GitHub refuses the comment, its text goes back to its form (`restoreCompose` for a comment box), or becomes a `refused` draft that a sidebar notice opens.
- **Notes row.** The `tr.notes` under a code row that holds the row's threads and the comment form being written in a band (`div.notes`), in the same chunk as the code row. When a render changes a band on screen, the band changes height over a moment (`animateNotes` in `page/80-main.js`).
- **Merge state.** What the author of a pull request needs to merge it, from `merge.fetch` (`GET /api/.../merge`): the checks of the head commit, each a check run or a commit status with a state (`passed`, `failed`, `cancelled`, `running`, `queued` or `skipped`), and for a failed check run its failing step and its failure annotations; the review decision and the latest approvers; whether GitHub can merge it (`mergeable`, `merge_state`); its auto-merge request; and the merge methods the repository allows. The page loads it only on the viewer's own pull request (`isOwn` in `page/55-merge.js`: the comments' viewer is the page's author), after the comments, and again every 20 seconds while the pull request is open and a check runs, auto-merge is on, GitHub has yet to work out whether it can merge, or the reader re-ran a check in the last 2 minutes. Its status wins over the comments' once it loads, and a status that differs loads the comments again.
- **Merge button.** On the viewer's own pull request, the button at the end of the sidebar's head that names where it stands (`mergeStanding`): Ready to merge, Checks running, Checks failed, Conflicts, Auto-merge on, Changes requested, Waiting on review, Behind or Blocked, a Draft, or Closed, with an icon in its tone; none once merged. It takes the place of the Review button, which stays beside it only while a pending review waits to go out, and opens the **merge panel**: the checks, a line for the review, a banner for conflicts or auto-merge, the commit message box (none for a rebase; left empty, GitHub writes its default message), and the buttons that merge, turn auto-merge on (only while GitHub blocks the merge, since GitHub refuses it for a pull request it can merge now) or off, reopen or mark ready, with the ⋮ menu of the merge methods the repository allows, the choice saved per repository as `dr:mergeMethod:<owner/repo>`. A merge asks to confirm first, and names the page's head commit, so GitHub refuses it once the branch has moved.
- **Verdict.** The viewer's latest approval or change request and the commit it reviewed (`verdict` from `comments.fetch`), or none when GitHub dismissed it. The Review button says Ready to review; while the verdict is on the head commit, it names the verdict instead, and the page and the server refuse the same verdict again (`headVerdict` in `page/50-comments.js`, `REPEATS` in `comments.py`). A pending review started before a push reviews the commit it started on, so its verdict, once sent, is on an older commit, as on GitHub.
- **Shell.** The tabbed document at `/` that holds the start page and one page per PR in iframes. Its two sides are `shell/tabs.js` (the strip and the frames) and `shell/frame.js` (what a page inside it does); the messages between them are known only to those two files. The desktop app's "Close Tab" menu item (Cmd+W) reaches the shell as a `close-tab` event on its window, and its "Settings…" menu item (Cmd+,) as `open-settings`, both sent from `src-tauri/src/main.rs`. A page reaches the shell through `SHELL`, null when the page is the top-level document. A page inside the shell carries `html.framed`, which its stylesheet reads to leave the shell's settings gear its corner.
- **Tab.** One entry in the shell's strip: the home tab for the start page, or a PR page, keyed by its path. A PR page reports whether it holds a **draft**, text the user typed and has not sent (`hasDraft` in `page/50-comments.js`); closing a tab with a draft takes a second close within a few seconds.
- **Theme.** The colour scheme (`light`, `gruvbox`, `claude`, `dark`) saved as `dr:theme`, Claude by default. Gruvbox and Claude are dark schemes, so the native window turns dark with them. `shell/theme.js` applies it in every document and keeps the native window and the other open documents in step; the palettes live in `render.py`. The picker is the first section of the Settings.
- **Tooltip.** The `.tooltip` that `shell/tooltip.js` shows for any element with a `title`, in every document the server sends: after the pointer rests on the element for 300 ms, or right away when the pointer comes back to the same element less than 500 ms after its tooltip closed. A title that repeats text the element shows in full shows only while some of that text is cut off. Give an element a `title` only when it tells the reader something the screen does not already show, such as the name behind an icon or a full name that may be cut off (the only kind of tooltip the file tree has); never draw a tooltip of its own.
- **Base stylesheet.** `shell/base.css`, in the head of every document (`theme_head` in `render.py`) next to the colour tokens: the non-colour tokens, the page basics (`body`, `a`, `.spacer`, `.hint`, `.kind`, `.err` for text that reports an error, important so that no document's rule turns it back to another colour) and the components below. A document's own stylesheet says where a component goes (margin, flex, width) and what colour a verdict or a status gives it, never a component's size, radius or text colour. The one colour a document may set is the canvas on a count, a reason pill or a field that sits on the inset, panel or hover surface, so it stays visible (the search field, the count on an open tab, a reason pill on a card under the pointer).
- **Non-colour token.** A custom property in the `:root` of the base stylesheet. Fonts: `--sans`, `--mono`. `--dim`, the opacity of content the reader can see but should skip. Corners: `--radius-sm` (chips, badges, key caps, inline code), `--radius` (controls: buttons, fields, menus, code blocks), `--radius-lg` (cards), `--radius-pill` (counts, reason pills and the status pill). Controls: `--control-font` and `--control-line`, the text of a button, a field and the status pill, which make a control 24px tall.
- **Button.** A `button`: control-sized text in a bordered box, laid out as a flex row so an icon or a count sits next to its label. `.primary` fills it with the accent, for the one action a place is for (Ready to review, Comment, Start a review, Open). `.on` tints it, for a toggle that is on (a filter, Mark reviewed, an open Review panel). `.ghost` drops the border and quietens the text, for icon buttons and side actions (the chevron, the editor, the settings gear, the close of a dialog, Show N more). A `.chev` is a ghost button that closes or opens what it heads, pointing down while `.open`, such as a file on the PR page, or the icon in the summary of a folded column, pointing down while the `details` is open; a document sets its size. `.big` is the start page's Open button. A `.seg` is a segmented control: buttons side by side in one bordered box, such as the editor with its menu. A `.menu` is a column of borderless buttons on a panel that a button opens, such as the editor menu. A context never changes a button's size or colours; the Review button's verdict colours and the merge button's tone are the exceptions, since each button names where the pull request stands.
- **Field.** An `input` or a `textarea`: control-sized text on the panel surface, the accent as its focus ring. A textarea is mono, since it takes code and comments, and fills its box; a document sets its height. `.big` is the start page's one field.
- **Card.** A `.card`: a bordered box on the canvas with the large radius, for a thread, a form, a comment of the conversation, the settings dialog, the start page's Recently opened list and each PR on the start page's board. `.panel` puts a card on the panel surface, to raise it over the quiet cards on the canvas. A card that is a link (`a.card`) keeps the text colour and takes the hover colour under the pointer. A `.banner` is a notice that something needs the reader, in the modified colour.
- **Count.** A `.count`: a number in a small rounded pill next to a label, with an icon before it at times, such as the files a filter matches, the pending comments of a review, the threads of a file, or the unresolved threads of a tab. `.hits` is the count of search hits, in the accent. Inside a button that is `.on` or `.primary` it swaps colours with the button. A `.split` is a count of added and removed lines.
- **Reason pill.** A `.reason`: a few words with an icon before them in a rounded pill on the inset, a little roomier than a count, cut off with an ellipsis when it runs out of room, its words as its title. The start page's cards show a reason pill for each reason a pull request is in its section, in the colour of its tone.
- **Tone.** A `.tone-bad`, `.tone-warn`, `.tone-ok` or `.tone-accent` in the base stylesheet: the text colour of a thing that reports how something stands, such as a reason pill, a check of the merge panel or the merge button.
- **Status pill.** A `.status` with `.st-<status>`: the pull request's status in its colour, with its icon, in the sidebar's head.
- **Pill and badge.** A `.pill` names a file or a folder in mono, in the colour of its change (`.st-A`, `.st-M`, `.st-D`, `.st-R`, `.st-V`), italic for a test file (`.test`); a renamed file's old name is an `<s>` inside it. A `.badge` is the letter of that change (`.A`, `.M`, `.D`, `.R`, `.V`) in a file's header.
- **Chip and tag.** A `.chip` is a small bordered note inside content: the rename marker on a dimmed line, or an inline fold, which is `.action` (a control, lit while `.open`). A `.tag` is a word in capitals in an outline, such as a pending comment's `.pending`. A `kbd` is a key cap, and a `code` is inline code: mono on the inset, plain inside a `pre`.
- **Modal.** A `dialog.modal`: a dialog that fills the window, dims it with `--backdrop` and centres what it holds, such as the settings and the image viewer.
- **Tooltip component.** `.tooltip`, the box that `shell/tooltip.js` draws: text-coloured fill, canvas text.
- **Colour token.** A CSS custom property that `palette()` in `render.py` defines for each theme; stylesheets and scripts name tokens, never colours (`tests/test_render.py` checks). Backgrounds: `--bg-canvas`, `--bg-panel` (sidebar, folds, cards), `--bg-inset` (code, pills, badges), `--bg-hover`, `--bg-hover-strong`. Text: `--text`, `--text-secondary`, `--text-muted`, and `--text-on-fill`, the canvas colour, for text on an accent, status or text-coloured fill (a primary button, the status pill, the tooltip), so a filled control reads as cut out of the page. `--border`. Accent: `--accent`, `--accent-hover`, `--accent-bg`. Selection: `--tree-active-bg`, `--tree-active-fg`, `--row-target-bg`, `--row-selected-bg`, `--comment-pending-bg`, `--search-hit-bg`, `--search-hit-fg`. Overlay: `--backdrop`, the dimmed window behind a modal. Diff: `--add-*`, `--del-*`, `--mod-*`, `--ren-*` (`-fg`, `-bg`, `-num`, `-word`). Syntax: `--syntax-kw`, `--syntax-str`, `--syntax-cmt`, `--syntax-num`, `--syntax-fn`, `--syntax-cls`, `--syntax-builtin`.
- **Editor.** An IDE or website the page can open a file in (`editors.Editor`, an `id`, a `name` and whether it is `local`): VS Code, Cursor or a JetBrains IDE, which are local and open the Checkout, or GitHub, which opens the file on github.com at the PR's head commit and is always installed. `editors.known()` lists every editor the app knows, in the order of the menu, and `editors.installed()` the ones with an installed app bundle; the server accepts only the id of an installed one. `editors.open_file` opens a file; a JetBrains IDE gets a file of a project it has open through its URL scheme, and `open_file` refuses the next file for the same JetBrains IDE and folder while the IDE still takes over the last one. The page saves the reader's choice in a file header's editor menu as `dr:editor`, forgets it once that editor is no longer installed, and uses the first installed editor while it has no saved choice.
- **Checkout.** The normal clone of a repository, with file contents, that an editor opens: `checkouts/<owner>/<repo>` in the cache (`Checkouts.folder` in `checkout.py`), next to the bare clone in `repos/` that builds pages. `checkout.checkouts`, a `Checkouts`, keeps one lock per repository. `Checkouts.held` holds that lock for a block and yields the repository's `Clone`. It is cloned in the background when a PR's page loads (`Checkouts.warm`, from `editors.prepare`), or else by the first open, into a temporary folder that is renamed once the clone is complete. `Clone.at_head` moves it to the PR's branch, and its docstring says when it refuses, when it moves a force-pushed branch, and when it skips the checkout.
- **Update.** A newer version of the desktop app, as the Homebrew cask names it (`update_check` in `src-tauri/src/update.rs`). The shell offers it in a small card at the bottom of the window (`drawUpdate` in `shell/tabs.js`) until the reader hides that version with Later (`dr:updateSeen`). The Update section, first in the Settings, shows the running version and offers the update even after Later; with no update known, its button checks the cask again at once (`update_check` with `force`). An install is **managed** when Homebrew installed it; only a managed install can run `update_run`, which quits the app and leaves a helper script to run `brew upgrade` and reopen it.
- **Settings.** The modal in the middle of the window that the shell opens from the gear in its bottom left corner, from the Settings button in the start page's footer, from Cmd+, (a page forwards the chord, or a click on the footer's Settings button, to the shell as a `settings` message) and from the desktop app's "Settings…" menu item. In the desktop app it opens with the Update section. A page may name a section of the body (`data-section`, such as `repositories`) in its `settings` message, and the modal scrolls to it once the body has loaded; the start page's repository strip opens the Repositories section this way. Its settings are the theme and the followed repositories; the rest shows the state of things: the shortcuts, the file type rules, the folded lines, the hidden files, the editors, the cache and the commit. The Update section and the theme picker are the shell's own, in `shell/tabs.html`; the rest is `GET /settings`, an HTML fragment that `settings.py` fills into `shell/settings.html` from the code and the saved settings on each open, so it never drifts from what the code does.
- **Followed repository.** A repository the reader named in the Settings, as `owner/repo` in lower case (`followed.parse` takes the name or the repository's URL). The list lives in `followed.json` in the cache (`followed.py`), in the order the names were added, each once. Before the first save, `followed.load` asks GitHub for the repositories where the viewer opened a pull request in the last 7 days (`github.repos_of_recent_prs`) and saves them as the list, unless the reader saved one while GitHub was answering; once the file exists, even empty, it is the reader's and GitHub is not asked again. The Settings show it as a field per repository with a ✕, and a field that adds one; every change sends the whole list to `POST /api/followed`, one request after the other, and the server saves it and answers the names saved, or refuses the whole list with `followed.NotARepository` when a text names no repository; the fields then go back to the list the server last saved. An emptied field is a removal. The start page's `unreviewed`, `others` and `merged_others` sections search these repositories, and its repository strip has a toggle for each.
