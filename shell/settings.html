Repositories

The start page lists the pull requests of these repositories that need a reviewer or that someone else reviews. Add a repository as owner/repo or by its URL. Until you change the list, it holds the repositories where you opened a pull request in the last 7 days.

    Shift+Cmd+FSearch the file paths.

    To comment on several lines, drag the + from the first line to the last, or click the first line number and Shift+click the last.

    File types

    The filters above the tree sort every file into one type.

    Documentation
    A file with:
      __DOCS_RULES__
    Tests
    Any other file with:
      __TEST_RULES__
    Implementation
    Every other file.

    Folded lines

    A fold is one row in place of lines you can skip. Click it to open the lines, and again to fold them.

    Unchanged lines
    The 4 lines next to each change stay; the rest fold. A block of 10 lines or fewer stays whole. The row names the Python classes and functions that start inside it.
    Import sections
    In Python, Java, JavaScript and TypeScript, every import section folds, even unchanged. The row counts the lines added and removed.
    Whitespace
    A change that only adds or removes spaces, tabs or line breaks.
    Rename fallout
    A change that only follows a rename: the same word changing the same way in at least two places, or a renamed file. The line that defines the new name stays open. Inside a real change, such a line shows pale with a rename mark.
    Moved code
    A block of 4 non-blank lines or more that appears again, unchanged, elsewhere in the pull request. The row names the other place.
    Folds close together
    Folds of one kind with only a few unchanged lines between them join into one row, which says how many places it covers.

    A fold stays open while it holds a comment thread or the comment you are writing, or while a button under the overview shows its kind; its row then names the fold and takes no clicks.

    The class or function above a change

    A change in a Python file also shows the lines above it, up to the start of the class, function or call it sits in, so you can read the signature without opening a fold. When that body is long, the lines between the signature and the 2 lines before the change fold into a chip:

    41 def recognise(self, volumes, *, dry_run=False):
    ⋯
    56 if volume.quantity == 0:
    57 continue
    58 volume.recognised = not dry_run

    The signature, the chip that holds the 14 lines of the body, the 2 lines before the change, and the added line.

    Hidden files

    Generated files
    A file with:
      __GENERATED_RULES__
    Files with only noise
    Files where every change is an import, rename fallout, whitespace or moved code, and files renamed or moved without a change.

    Editor

    The </> button in a file's header opens the repository in your editor, on the pull request's branch, at the first changed line. You can pick an editor with ⋮, and differ will save it as your default. GitHub opens the file on github.com instead.

    Supported
    __EDITORS__

    differ keeps one clone per repository, made in the background when you open a pull request, and checks out the branch each time, also after a force-push, but not for a fork. It never discards your work: when the clone has uncommitted changes on another branch, or when the update would lose commits, it leaves the clone alone and shows the error.
