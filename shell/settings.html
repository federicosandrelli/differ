File types

The filters above the tree sort every file into one of three types. A file is documentation when it is:

    __DOCS_RULES__

Any other file is a test when it is:

    __TEST_RULES__

Every other file is implementation.

Folded lines

differ folds some lines into a single row. Click the row to open it, and click it again to fold the lines back. differ folds lines in these cases:

  • Unchanged lines. Between two changes, differ shows the 4 unchanged lines next to each change and folds the rest. It shows a block of 10 unchanged lines or fewer in full. The fold row lists the Python functions and classes that start inside it.
  • Import sections. In Python, Java, JavaScript and TypeScript files, every import section folds to one row, even when nothing in it changed. The row says how many lines were added and removed.
  • Whitespace. A change where every line is blank, or where each removed line equals its added line once all spaces, tabs and line breaks are removed.
  • Rename fallout. A change where each removed line becomes its added line exactly by applying a rename. A rename counts when the same word changes the same way in at least two places in the pull request, or when it follows a renamed file. The change that renames the definition itself (the class, def, or assignment) stays open.
  • Moved code. A block of removed lines that appears again, unchanged, as a block of added lines somewhere else in the pull request, in the same file or another one. The block needs 4 lines or more that are not blank. The fold row names the other place.
  • Several folds close together. When folds of the same kind are separated only by a few unchanged lines, they fold into one row that says how many places it covers. Opening it gives each place its own row.

Inside a real change, a line that only follows a rename appears pale, with a "rename" tag.

A fold always stays open when it holds a comment thread or the comment you are writing. The numbers in the overview count the lines of every file but the generated ones, and the buttons under them show or hide each kind of noise in every file at once. While a comment or one of these buttons keeps a fold open, its row only names the fold, and clicking it does nothing.

The class or function above a change

differ also shows the lines above each change, up to the start of the innermost class or function that holds it. Outside any class or function, it shows the lines up to the start of the call that holds the change, such as a long setup(...). You can then read the class line, the signature or the call without opening a fold. This works in Python files, for changes that add lines and are not noise.

When the body above the change is long, differ shows the class line, the signature or the first line of the call, and the 2 lines before the change. The lines between them fold into a chip on its own line. Click the chip to show the lines, and click it again to fold them.

Hidden files

By default, differ hides two kinds of files:

  • Generated files. These are lock files, files marked as generated in .gitattributes, and files that say near the top that a tool generated them (for example "DO NOT EDIT").
  • Files with only noise. These are files whose only changes are imports, lines that follow a rename, whitespace, or code that moved without other changes.

A notice above the file tree says how many files are hidden. Click "show" in the notice to show them.

Editor

The </> button in a file's header opens the whole repository in a new window of your editor, on the pull request's branch, at the first changed line of the file. The ⋮ next to it lists the editors installed and GitHub, which shows the file on github.com at the pull request's head commit, at the same line, in your browser. Choosing one opens the file in it, and differ keeps it as the editor for every file on this computer. Deleted files have no button.

    __EDITORS__

differ keeps one clone of each repository for this, made in the background when you open a pull request, and checks out the pull request's branch in it each time, with any new commits, also after a force-push, except to a pull request from a fork. differ never loses your work there: when the clone has uncommitted changes on another pull request's branch, or when bringing the branch up to date would lose your changes or commits, differ leaves the clone as it is and shows the error.
